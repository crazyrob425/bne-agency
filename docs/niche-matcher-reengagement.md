# Niche Matcher — Progress Saving & Automated Re-Engagement

## What was built
- **Local auth** (name / email / custom password) coexisting with Manus OAuth.
- **Real-time progress persistence**: every quiz answer saved (debounced) to
  `quiz_progress`, keyed by `lastCompletedQuestionId` for resume.
- **Automated re-engagement**: on abandonment, a full email schedule is computed
  and queued in `email_reminders`, then dispatched by a cron worker.
- **Structured contacts**: registrants/abandoners become `subscribers` rows, ready
  for newsletters + site-update campaigns.
- **Luxury email templates** with a gold CTA + two randomized "Niche Cards" teasers
  pulled from the real niche database (1020 top-earning niches).

# or apply directly:
mysql -u <user> -p <database> < drizzle/0001_niche_matcher_reengage.sql   # (generated by drizzle-kit)

New tables: `account_credentials`, `quiz_progress`, `subscribers`, `email_reminders`.

## 2. Activate the scheduler (cron)
Worker: `processDueReminders()` in `server/_core/reengagement.ts`. Sends every
`email_reminders` row where `status='pending'` AND `sendAt <= now`, then marks `sent`.
Invoke on a schedule via the admin-guarded tRPC endpoint:

```
POST /api/trpc/system.processReminders
Authorization: Bearer <admin-or-cron-session>
```

Cron example (every 15 min):
```cron
*/15 * * * *  curl -fsS -X POST https://blacklisted.studio/api/trpc/system.processReminders \
  -H "Authorization: Bearer $CRON_TOKEN"
```

## 3. Cadence (as specified)
- **+24h** — Initial high-energy luxury email (`kind='initial'`, window `d24h`).
- **Every 3 days for weeks 1–2** — High-conversion CTA (`kind='cadence'`, `w1-2`):
  days 3, 6, 9, 12.
- **Weekly for weeks 3–6** — Softer brand email (`kind='weekly'`, `w3-6`):
  days 21, 28, 35, 42.
Total: 9 emails over ~6 weeks, recomputed idempotently on each abandonment.

## 4. Email content
- Templates: `server/_core/emailTemplates.ts`. Fully inline-CSS gold/black luxury.
- Teasers: `server/_core/nicheTeaser.ts` — 2 random high-earning niches per send.
  Snapshot regen: `node scripts/genNicheSnapshot.cjs`.
- Delivery: `server/_core/mailer.ts`. Set `SMTP_*` env to send for real; otherwise
  logged (dev fallback). Swap transport for Resend/SES/Postmark there.

## 7. Reliability guarantees (added in optimization pass)
- **No double-sends**: `processDueReminders` claims rows with a single atomic
  `UPDATE ... WHERE status='pending' AND sendAt<=now ORDER BY sendAt LIMIT n` that
  flips them to a transient `sending` state. Concurrent cron workers can never grab
  the same row. A crash mid-send leaves the row in `sending` and it is retried on the
  next run (at-least-once delivery).
- **Signed unsubscribe**: the `?t=` token is HMAC-SHA256 signed (not reversible
  base64), so it can't be forged and doesn't leak the email. Verify + opt-out via
  `POST /api/trpc/auth.unsubscribe` (sets `subscribers.status='unsubscribed'` and
  cancels pending reminders).
- **Bounded concurrency**: SMTP sends run with a pool of `SEND_CONCURRENCY=5`; the
  transport is a reused pooled nodemailer instance (not recreated per email).
- **Robust exit capture**: the client fires the abandonment signal on
  `visibilitychange→hidden` and `pagehide`, flushing the latest progress first, so
  the email schedule triggers reliably even on mobile backgrounding / tab close.
## 6. Notes / compliance
- Passwords: scrypt (per-user salt); upgrade to argon2id via `server/_core/password.ts`.
- `subscribers.status` supports double opt-in; every email has an unsubscribe link.
- `markAbandoned` requires a captured contact email; scheduling is skipped otherwise.
